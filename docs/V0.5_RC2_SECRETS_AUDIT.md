# Velora v0.5 RC2 Secrets Audit

## Rule
Because the repository is public, any credential found in reachable Git history must be treated as exposed until rotation/revocation is confirmed. Do not use recovered credentials in tests or demos.

## Inventory
| Secret class | Current RC2 tree | Historical status | Required state |
|---|---|---|---|
| Supabase `service_role` key | Not found by current-tree scan | Unverified until full-history Gitleaks completes | **Rotate immediately if ever present** |
| Supabase JWT secret | Not found by current-tree scan | Unverified | **Rotate immediately if ever present** |
| Supabase anon/public key | No hardcoded credential assignment observed | Unverified in history | Keep public values only where intended; rotate if sensitive value was exposed |
| Stripe secret/live key | Not found by current-tree scan | Unverified | **Rotate immediately if ever present** |
| SendGrid/API mail key | Not found by current-tree scan | Unverified | **Rotate immediately if ever present** |
| Private keys/certificates | Not found by current-tree scan | Unverified | **Revoke/rotate immediately if ever present** |
| Demo passwords/credentials | Not found by current RC2 tree | Earlier import history contains deleted archive material; exact contents require Gitleaks/history scan | Treat as compromised until proven otherwise |

## Evidence
- Current-tree scan on RC2: `0` findings.
- The repository is currently public.
- The baseline import history contains deleted `.velora-import` archive chunks. Those historical blobs are not treated as safe merely because they were deleted later.
- A complete historical verdict requires a full Git clone plus Gitleaks scan.

## Required CI controls
1. Gitleaks over full history (`fetch-depth: 0`).
2. CodeQL analysis on the repository.
3. Dependabot updates enabled.
4. No secrets printed to workflow logs; use masked GitHub/Supabase secrets only.

## Credential handling status
Previously rotated/revoked authentication sessions and passwords remain out of test use. Service-role, JWT-secret, Stripe, SendGrid, and other provider credentials remain **pending historical verification/rotation** unless independently confirmed in the provider dashboards.
